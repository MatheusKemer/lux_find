lux_find

Full-text search over the notes, code and chats you already have. One SQLite file. No server, no cloud, no dependencies.

The answer to "how did we decide that?" is almost always already on your disk, and almost always unfindable.

The pipeline

Sources

whatever you already keep on disk

  • markdown and plain-text notes
  • your own repositories
  • agent transcripts
  • chat data exports
  • declared in one small config
→

Connectors

two methods, about thirty lines each

  • scan: what exists, has it changed
  • load: give me the chunks
  • the split is what makes incremental indexing possible
  • add your own for e-mail, bookmarks, issues
→

Process

into one searchable unit

  • notes chunked by heading
  • code by sliding window with overlap
  • conversations one chunk per message
  • identical documents collapsed by hash
→

Privacy

applied before the index, not before display

  • credential files never opened
  • no network code anywhere
→

Index & query

one file, milliseconds

  • SQLite FTS5, BM25 ranking
  • incremental by mtime and size
  • human output, or --json for agents
  • stale index warns, broken index exits 3

What it looks like

$ lux-find find "why tombstone instead of hard delete"
lux_find "why tombstone instead of hard delete" - 8 hits - 1.5 ms - confidence medium

1. ~/exports/agent-session.jsonl:1  [chat] - today
   user: why did we pick a tombstone instead of a hard delete?

2. ~/notes/design/sync-protocol.md:17  [note] - today
   ## Rejected alternative  We chose a tombstone instead of a hard delete because ...

Performance

Apple-silicon laptop, Python 3.12, SQLite 3.49, over a generated corpus of dense synthetic prose - a deliberately unfriendly shape where every query term matches a large fraction of the corpus. Real notes are more selective and usually faster. No benchmark harness needed to check your own: index prints its elapsed time, find prints the query time in its header, status prints the index size.

Privacy model

Nothing leaves the machine

Not a promise - an absence. There is no HTTP client, no socket, no telemetry and no update check in the package, and continuous integration fails the build if one appears. Verify in ten seconds: grep -rnE '^\s*(import|from)\s+(socket|urllib|http|requests)\b' src/
